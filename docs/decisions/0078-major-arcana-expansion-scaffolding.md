# 0078: The Major Arcana expansion is generated, placeholder-flagged where content is pending, and templated for the remaining units

## Context

Simon asked to build out the rest of the v4 path beyond Fool/Lovers/Empress:
one new card per unit, same lesson formats, 3-card end-of-unit readings that
bring back earlier cards, scoped to finishing the 22 Major Arcana (units
9-27). New characters were considered and dropped — Dave and Riley continue
to alternate through the whole course (there's no image-generation tool
available in this environment to produce new character art at Dave/Riley's
fidelity).

Only 5 of the 22 majors (Fool, Lovers, Empress, Magician, Emperor) had any
existing hand-authored round content. The other 17 needed lesson content
built from scratch, at a scale where hand-authoring every round risked
inconsistent quality and a huge unreviewable diff.

## Decisions

**Lesson content for the 17 new cards is generated by
`scripts/build-v4-new-cards.mjs`, not hand-written**, reading
`data_card_talking_points.csv`, `data_card_similarity.csv`, and each card's
own keyword table directly — the same source-of-truth rule as everything
else in `data/`. Distractors for cloze/choice/swipe rounds are pulled from
*other real majors' own real content*, chosen by walking
`data_card_similarity.csv` sorted by closeness (note: `similarity_score` is
inverted from its name — 1.0 is the hardest/closest pair, 3.0 is easiest;
sort ascending for "closer distractor"). Nothing in the generated rounds is
invented copy: every keyword, cloze blank, and choice option traces back to
a CSV cell.

**The zone round ("Find the Elements") is kept, not dropped, for the new
cards** — Simon: "the curriculum is missing elements." Since real per-card
element-zone data doesn't exist yet (Simon has a separate extraction process
building it), each new card's zone round ships as an explicit placeholder —
two dummy zones with copy that says as much ("Element pending — real content
lands once the extraction pass for this card is done") — rather than
skipping the round shape or faking real-looking data. This keeps every new
unit's node count and format sequence identical to Fool/Lovers/Empress, so
nothing downstream (progress tracking, capstone wiring) has to special-case
the new cards. **When the extraction process delivers real element data,
replace the `elements` array in each affected `data/v4/<slug>_section.json`
node-2 — nothing else in that file should need to change.**

**Fool/Lovers/Empress's own `_section.json` files are hand-edited and must
never be regenerated.** `scripts/build-v4-sections.mjs` and
`scripts/build-v4-capstone-nodes.mjs` both unconditionally overwrite their
entire output from a hardcoded 3-card list — rerunning either wipes any
hand-edits. This was hit twice this session. Neither script should be run
again; `build-v4-new-cards.mjs` merges into `capstone_nodes.json` rather
than overwriting it, and any future one-off data script should follow that
same merge pattern.

**The end-of-unit narrative gets a mechanical twist for units 9+**: the
first narrative node of a unit is still a single-card reveal + Q&A for that
unit's new card (unchanged shape from units 1-8). The *end* node becomes a
real interactive 3-card draw using `chapter-player.jsx`'s `draw` beat type
(`slot`/`prompt`/`answer` against a shared `availableCards` pool) — built
but never exercised until now. The three slots are Past/Present/Future,
filled oldest-to-newest from the character's last two taught cards plus the
new one; `availableCards` includes the 3 correct answers plus 2
already-taught decoy cards. All post-draw Q&A concentrates on the new card
only, not all three — the reading recalls old cards, but the *teaching*
stays scoped to what the unit is actually introducing. `u9-dave-start.json`
/ `u9-dave-end.json` (Magician) are the validated reference implementation
for units 10-27.

## Why this over the alternatives

Hand-authoring 17 cards' worth of rounds directly would have been slower and
harder to review at this volume, and more prone to silent quality drift
across cards than a single reviewable generator plus a structural validator
(a custom script checked every generated file for duplicate words, missing
correct answers, cloze blanks that don't appear in their own text, and
swipe/choice balance — see the session log, not reproduced here). Dropping
the zone round for the new cards would have been the easier path but was
explicitly rejected — consistency of format across every unit matters more
than shipping the 17 new units without a real zone-round shape.
