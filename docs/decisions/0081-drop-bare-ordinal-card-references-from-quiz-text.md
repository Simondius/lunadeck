# 0081: A card's own description can't lean on "the Two" or "of Four" once it's lifted into a round

## Context

Simon flagged a screenshot of the Empress's node-1 cloze round: "Card three
follows the private ___ of the Two with ___ itself, and the Empress is
Mother Earth incarnate." Out of context this reads like it's talking about
positions in a multi-card spread ("card two", "card three"), not what it
actually means — the Empress is the Major Arcana's third card, following
the High Priestess as its second. That framing is genuine content from
`data_card_descriptions.csv`'s `description_condensed` column (and its
fuller `description_text` says the same thing more explicitly: "The
Empress carries the number three of the Major Arcana... follows the
intimate reflection of two"), and it reads fine in the guidebook's own
flowing prose. It doesn't survive being lifted into a standalone quiz
round with nothing around it to say what "the Two" even refers to — and
this app's curriculum never explains Major Arcana deck-position numbering
anywhere (the closest existing gap of this kind is the already-documented
one where Format A3 asks "Major or Minor Arcana?" without the course ever
teaching that distinction).

Checked every one of the 22 majors' own `description_condensed` for the
same shape of problem (a bare ordinal standing in for another specific
card, not just a number appearing in clear context — "Two horses pull it"
in the Chariot's own description is fine, it's describing the card's
imagery, not referencing another card). Two hits, both now fixed:

- **The Empress** (hand-authored, in `data/v2`, `data/v3`, and
  `data/v4`'s own `empress_section.json` identically): "Card three follows
  the private reflection of the Two with creation itself."
- **The Hierophant** (`data/v4/hierophant_section.json`, generated by
  `scripts/build-v4-new-cards.mjs` from the same CSV column): "After the
  stability of Four, the Hierophant introduces the first real crisis..."

Every other major's condensed description that mentions a number does so
by naming the card directly alongside it ("After the Wheel's turning
point...", "the second-to-last Major Arcana card yet arguably the true
conclusion of the Fool's journey") — those are left alone.

## Fix

Drop the confusing opening clause, keep everything after it — the rest of
each sentence is unaffected real content, not something invented for this.

- Empress's two affected rounds (the short 3-blank intro cloze and the
  longer 9-blank node-7 recap, both under `id: "n7-r1"` and `"n7-r4"`)
  now open directly at "The Empress is {blank} incarnate..." The intro
  round shrinks from 3 blanks to 1 (`reflection`/`creation` no longer
  exist in the round's own text to blank); the recap shrinks from 9 blanks
  to 7. Distractor counts were left as they already were — 3 distractors
  for a 1-blank round already matches this app's own convention elsewhere
  (see any single-blank keyword-in-context round in `build-v4-new-cards.mjs`'s
  own output).
- Hierophant's node-7 recap is generated, not hand-authored, so the fix
  lives in the generator itself: a small `DESCRIPTION_OPENER_OVERRIDE` map
  in `scripts/build-v4-new-cards.mjs` swaps in a trimmed version of the
  card's own `description_condensed` before it reaches the recap-cloze
  builder, rather than patching the generated JSON directly (which
  `0078`'s own rule against hand-editing generated output would make
  unsafe to keep). Rerunning the script after this change touched only
  `hierophant_section.json` — confirmed via `git diff --stat`.

## Verification

`grep` for both original opening phrases across every `data/v2`, `data/v3`,
`data/v4` JSON file returns nothing; all four touched files still parse as
valid JSON; `check_data.py` and `npm run build` both still pass.
